Data Protection Lifecycle:
    - Current Data Storage
    - If database or table is accidentally dropped
    - If table is truncated or updated accidentally
    
Time travel enables accessing historical data:
    - Query deleted or updated data
    - Restore tables, schemas and databases that have been dropped
    - Create clones of tables, schemas and databases from previous state

Considerations:
    - Undrop fails if an object with the same name already exists
    - Ownership privileges are needed for an object to be restored


Things to keep in mind:
    - Copying data from external sources to the table
    - Ensure File Formats are defined and are used to transfer data into/from tables from/into stages
    - Use On_Error, SIZE_LIMIT, TRUNCATE keywords judiciously while working copying into the tables
    - Put Proper Clustering Logic on Columns while working with Tables 
    - Validation of Snowpipe still working and check a Pipe is paused or is running
    - Undrop Tables
    - Set Retention Time for tables while creation
    - Get Table specific Data Used and Resource usage details (refer 39_time_table_cost)
    - Make sample of the table for analysis and test it as a proof of concept
    - See details about specific tasks (how many times it got trigerred) (refer task_history_error_handling_61)
